## Approved Requirement Checkpoints

### Master Data

- One workbook represents one Product.
- The selected Product is checked against the workbook Product Code during import.
- A mismatch blocks the import before state mutation.
- Each import targets one role: `Reference` or `Current`.
- Reference and Current are separate datasets.
- Import, manual editing, cloning, and Draft workflows remain flexible.
- Missing/Invalid values are retained visibly; no silent zero fallback.

### Cost Breakdown

- The page compares a valid `Reference` dataset with a valid `Current` dataset for the same Product.
- Core Cost Structure is stable: `Material`, `Labor`, and `Burden`.
- Users do not add or remove Core Cost Elements from Cost Breakdown.
- Reference and Current are calculated independently.
- The comparison covers all supported data, with `All Data` and `Changed Only` views.
- The UI shows Before/After, Gap, status, and grouped Source details without repetitive source text.
- Comparison statuses include Unchanged, Modified, Added, Removed, Reordered, Moved Work Center, and Need Review.
- Routing uses Work Center data from the same dataset side and must not be double-counted.
- Missing/Invalid values must not become verified-looking numeric fallbacks.
- Export, Simulation, RCA, and Candidate Selection are outside this page checkpoint.

### Financial and Simulation Direction

- Sale, COGS, Gross Profit, SG&A, OP, Profit, and additional variables must be supported somewhere in the web application.
- They are not part of the fixed Core Cost Breakdown table by default.
- Their final Calculation/Simulation placement and formulas require a later page review.
- Simulation must remain isolated from official Reference/Current/Active data.
