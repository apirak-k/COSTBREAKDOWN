## Comparison Scope: Before / After Across Three Working Datasets

Cost Breakdown answers: *“What changed between the selected Before and After datasets, and where does the Standard Cost gap come from?”*

CBD reads the latest Master Data Working snapshots for Reference, Current, and Custom. Save is not a publish gate. CBD comparison selectors change only CBD analysis state; they do not edit, clone, save, publish, or create a dataset.

The ordered choices are all nine pairs:

- Reference → Current (default)
- Current → Reference
- Reference → Custom
- Custom → Reference
- Current → Custom
- Custom → Current
- Reference → Reference
- Current → Current
- Custom → Custom

Each side is selected independently. Self-comparison is allowed and the opposite side never auto-swaps. The core comparison engine receives Before as its first snapshot and After as its second snapshot. Therefore:

$$\text{Gap} = \text{After Cost} - \text{Before Cost}$$

- Positive Gap means After cost is higher; negative Gap means After cost is lower.
- `ADDED` means a record exists only on After; its absent Before contribution is zero.
- `REMOVED` means a record exists only on Before; its absent After contribution is zero.
- Self-comparison yields zero monetary gaps where calculations are available, matched records are `UNCHANGED`, and it creates no artificial Added/Removed findings. A zero percentage denominator displays unavailable (`—`).
- An absent record is distinct from a missing required input inside an existing record; missing inputs leave calculations unavailable.
- Each side calculates with its own Work Center rates.
- Shared calculation formulas, business identities, and missing-input safeguards follow [CROSS_CUTTING.md](CROSS_CUTTING.md) and [FINAL_LOGIC_SPEC.md](FINAL_LOGIC_SPEC.md).

## Comparison Statuses

Use only:
- `UNCHANGED`
- `CHANGED`
- `ADDED`
- `REMOVED`

Status and Gap are independent:
- A `CHANGED` finding can have positive, negative, zero, or unavailable Gap.
- When a Work Center rate change causes a Process's calculated processing cost to change, that Process is `CHANGED` even if its own Routing-owned fields are unchanged. The Work Center remains rate owner and context, not a Candidate.
- Field differences are details under `CHANGED`, not separate statuses. Do not invent a `REPLACE` status or infer split/merge relationships.

Keep unchanged records available in the normal comparison data and for status filtering. The compact Status dropdown contains only four multi-select options (`Changed`, `Added`, `Removed`, `Unchanged`) and starts with all four selected; it has no heading, separator, or explanatory footer. Its closed label is `Status (All)` for all four, otherwise `Status (1)`, `Status (2)`, or `Status (3)`; `Status (4)` is not shown. At least one status remains selected, so the final deselection is prevented and `Status (0)` cannot be reached. Pointer-down on an unchecked option selects crossed options; pointer-down on a checked option deselects crossed options. That intent stays fixed for the gesture, each option is visited at most once, and keyboard checkbox operation remains available. Release, cancellation, and window blur end the gesture.

## Processing and Work Center Context

- Calculate processing cost independently on each side using Routing operations and Work Center rates.
- Routing `Process` is the primary process-level record and finding in Itemized Comparison. Match it by its approved Process identity; its Work Center assignment and the rate from that Work Center on each side are calculation inputs and explanatory details.
- If a Process moves to another Work Center, retain one matched RTG finding for that Process and classify the changed assignment as `CHANGED`; do not split the move into a removed/added pair. A Work Center rate change can also make an otherwise unchanged Routing record's calculated cost `CHANGED`.
- Aggregate processing by Work Center, then compare the selected Before and After totals:
  $$\text{WC Net Gap} = \text{After WC processing total} - \text{Before WC processing total}$$
- Work Center processing is separate aggregate context, not a parent for the Process findings and not a Candidate. Display full-snapshot Conversion Cost by Work Center / Before / After / Gap, with a compact Total when available. Candidate selection does not filter or recalculate this context.
- Detailed effects reconcile to their parent totals:
  $$\text{Material Gap} + \text{Labor Gap} + \text{Burden Gap} = \text{Total Gap}$$
  $$\text{Labor Gap} + \text{Burden Gap} = \text{Conversion Gap}$$
  $$\text{Changed effects} + \text{Added effects} + \text{Removed effects} = \text{Parent branch Gap}$$
- If detail cannot reconcile due to missing/invalid calculation inputs, display an unavailable or validation state instead of guessing.
- Expanded parameter details use the existing additive LMDI monetary attribution for matched `CHANGED` BOM and RTG records; other statuses keep their existing one-sided or unavailable values without invented attribution.
- Expanded BOM detail uses Before → After / Parameter Cost Effect rows and Usage / Price / Loss / Gap columns. BOM cost is `Usage × Price × (1 + Loss)`. LMDI allocates the actual BOM record material gap across Usage, Price, and `(1 + Loss)`. Parameter Cost Effect Gap is the actual record Candidate Cost Gap; do not derive it by summing display-rounded factor effects. Unit is omitted.
- Expanded Routing detail uses Before → After / Parameter Cost Effect rows and Manning / Capacity / Yield / LB Rate / BD Rate / Gap columns. For RTG, `Factor = Manning / (Capacity × Yield)`, `Labor = Factor × Labor Rate`, `Burden = Factor × Burden Rate`, and `Conversion = Labor + Burden`. Calculate additive LMDI independently for Labor and Burden using Manning, inverse Capacity, inverse Yield, and the corresponding Work Center rate; Conversion attribution for each factor is the sum of its Labor and Burden effects. The Parameter Cost Effect row exposes all five existing factor effects; their unrounded sum reconciles to the actual process Candidate Conversion Gap in the Gap cell. Rates are resolved against each snapshot's unique Work Center match. Do not add separate Rate Effect or Total Effect rows. Missing or invalid factor inputs remain unavailable.
- Candidate `%GAP` is the actual Candidate Cost Gap divided by the full Standard Cost Gap. A zero or unavailable denominator displays unavailable (`—`). Signed contributions, including negative values and values above 100%, remain visible. The CBD UI does not display `% Parent`.
- LMDI attribution requires every required input on both sides to be positive and finite. Missing, zero, or non-finite required inputs make that record's Parameter Cost Effect unavailable; do not coerce them to zero. This attribution availability rule does not replace the underlying cost calculation or validation rules.

## Full State and Selected Candidates

- Full state is the default comparison covering the complete selected Before and After snapshots; the default pair is Reference → Current.
- Selecting a BOM or RTG Candidate immediately adds it to the temporary Selected Comparison scope; matched `CHANGED` / `UNCHANGED` findings move as Before / After pairs, while `ADDED` and `REMOVED` findings are independently selectable.
- The full Standard Cost Gap, full Cost Element and Work Center blocks, full finding rows, and full Work Center context stay visible. The selected scope is overlaid within the single Gap Bar and appears as secondary information only in Cost Element.
- Deselecting all Candidates returns to Full state. Type and Status filters do not remove selected findings that are temporarily hidden.
- Selected Comparison is scoped to the current ordered pair and does not mutate, save, or export any source dataset. Changing either selected role or its Working data clears selected membership. Pair changes also clear manual Candidate order/history and expanded details, while Type, Status, and Sort remain selected. It is an analysis scope, not a dataset and not an RCA Case.
- Navigation is not a reset: page-local CBD state is held in memory while navigating between app pages. Navigation alone preserves the Before / After pair, type and status filters, sort, Candidate selection and manual order/history, overview collapse state, and expanded details. No page-local state is added to session storage. A product, pair, or Working-source context change invalidates dependent state: Selected Comparison is reconciled against its pair/source fingerprint, while manual order/history and expanded details are cleared when their comparison basis changes.
