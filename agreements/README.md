# Agreement decision sources

> **HISTORICAL DECISION RECORDS — PRESERVE AS PROVENANCE, NOT CURRENT IMPLEMENTATION INSTRUCTIONS.**
> The agreement bodies below record decisions as originally made and may contain behavior later
> superseded. Do **not** implement content that conflicts with the current canonical specifications.
> Resolve conflicts using [`docs/REQUIREMENTS_INDEX.md`](../docs/REQUIREMENTS_INDEX.md),
> [`docs/specs/FINAL_LOGIC_SPEC.md`](../docs/specs/FINAL_LOGIC_SPEC.md), and the relevant current
> page spec. The historical bodies are intentionally retained without rewriting their original
> decisions.

These files preserve the original decision records and their status labels. Age, archive location, or absence from `docs/specs/` does not invalidate a previously finalized decision. A finalized decision remains in force unless a later explicit user decision supersedes that specific behavior.

The canonical specs are the consolidated, user-readable product contract. Keep migrating every still-valid finalized decision into them. Until migration is complete, an omitted decision is a documentation gap, not `PENDING/TBD`. Once migrated, these agreements remain provenance for where the decision came from.

Some specific Master Data schema, identity, workbook, and export decisions, and the older Routing Operation Code identity, were superseded by later explicit decisions. See the authority and supersession notes in [docs/REQUIREMENTS_INDEX.md](../docs/REQUIREMENTS_INDEX.md); do not treat an entire agreement as invalid because one detail changed.
